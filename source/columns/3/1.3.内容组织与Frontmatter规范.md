# 内容组织与 Frontmatter 规范

在 RustPress 中，所有的文章内容均由纯 Markdown 文件承载。通过在文件头部定义 **Frontmatter（前言元数据）**，您可以精确控制文章的标题、发布时间、分类标签、版式布局（Layout）以及是否作为草稿隐藏。

---

## 📑 1. Frontmatter 语法与核心字段

RustPress 原生支持 **YAML**（以 `---` 包裹）和 **TOML**（以 `+++` 包裹）两种 Frontmatter 格式。以下是一个标准的 YAML Frontmatter 示例：

```yaml
---
title: "深入理解 Rust 所有权与生命周期"
date: "2026-08-28 14:30:00"
createTime: "2026-08-28 14:30:00"
layout: post
draft: false
tags: ["Rust", "系统编程", "内存安全"]
categories: ["技术", "后端"]
slug: "deep-dive-into-rust-ownership"
description: "全面剖析 Rust 语言的核心支柱：所有权系统、借用检查器与生命周期推导机制。"
cover: "/static/images/rust-ownership-banner.png"
---

这里是文章正文 Markdown 内容……
```

### 常用字段说明表

| 字段名称 | 类型 | 必须 | 说明与示例 |
| :--- | :--- | :--- | :--- |
| `title` | `String` | 推荐 | 文章标题。若未提供，系统会自动提取正文中的第一个 `# 一级标题`，或回退为文件名。 |
| `date` / `createTime` | `String` | 推荐 | 发布/创建时间，支持 `YYYY-MM-DD HH:MM:SS` 或 `YYYY/MM/DD` 格式。系统依据此时间进行时间轴排序与归档统计。 |
| `layout` | `String` | 否 | 渲染使用的模板名称（默认为 `post`）。支持 `post`, `columns`, `doc`, `tweet`, `friends`, `works`, `projects` 等。 |
| `draft` | `Bool` | 否 | 草稿标记。若设为 `true`，在生产构建时自动排除，但在本地开发预览（`localhost`）中可见并带有草稿徽章。 |
| `tags` | `Array` | 否 | 标签列表，例如 `["Rust", "WebAssembly"]`。会自动汇总至 `/tags/` 索引页与标签分页列表。 |
| `categories` | `Array` | 否 | 分类层级列表，例如 `["tech", "rust"]`。若未指定，系统会自动根据文件所在的物理子目录路径推导。 |
| `slug` | `String` | 否 | 自定义 URL 路径段。默认为文件名（不含扩展名），例如 `slug: "my-post"` 生成 `/my-post.html`。 |
| `description` / `summary` | `String` | 否 | 文章摘要与描述，用于 SEO `meta description`、社交分享卡片（Open Graph）及列表页摘要。 |
| `cover` | `String` | 否 | 文章封面图片 URL 或相对路径。 |

## 📂 2. 文章源文件存放目录规划

RustPress 对文件存放非常宽容，无论您将 Markdown 放在扁平根目录下还是深层子目录中，都能自动识别：

### 推荐的目录规划方式：

1. **按年份/月份归档**（适合流水式个人博客）：
   ```text
   source/
   └── 2026/
       ├── 01.md
       ├── 02-why-rust.md
       └── assets/          # 存放当期插图
           └── flow.png
   ```
   - 生成 URL：`/2026/01.html`, `/2026/02-why-rust.html`。

2. **按分类目录组织**：
   ```text
   source/
   └── tech/
       └── rust/
           └── async-runtime.md
   ```
   - 系统自动提取分类为 `["tech", "rust"]`，生成 URL：`/tech/rust/async-runtime.html`。

3. **专栏与系列教程目录**：
   ```text
   source/
   └── columns/
       └── 1/
           ├── README.md    # 专栏总览页
           ├── 1.序言.md
           └── 2.核心概念.md
   ```

## 🔄 3. 核心机制：RustPress 倒分页（Reverse Pagination）

传统静态博客生成器在分页设计上通常遵循“新文章直接插在第 1 页，历史文章顺延”的机制。这导致了一个严重的 SEO 弊端：

```text
传统博客分页的问题：
[新增 1 篇文章] ──> Page 1 变化 ──> Page 2 内容全部整体后移 1 篇 ──> Page 3, 4... 全部变更！
结果：搜索引擎每一次爬取，所有历史分页的 Hash 全部改变，产生巨量无效抓取。
```

### RustPress 倒分页解决方案：

1. **首页永久最新**：
   `index.html` 始终展示最新发布的文章，满足读者的日常阅读与即时追踪需求。
2. **历史分页编号与内容永久固化**：
   - 博客初创期的第一批文章被固定分配在 `index2.html`（或编号最小的历史页）。
   - 后续文章累积后，依次向前递增生成新的历史分页。
   - **一旦一个历史分页生成，其包含的文章列表永久不变**。
3. **极佳的 CDN 缓存命中率与 SEO 友好度**：
   搜索引擎蜘蛛抓取历史分页只需抓取一次即可长期缓存，永久避免死链与内容飘移。
