# RustPress 配置与使用指南

写静态博客的人，写得久了大概率都经历过这样一种崩溃：文章写到十几篇时，本地预览秒开；等积累了上千篇长文，敲下 `build` 之后，笔记本发出飞机起飞的轰鸣，编译一次的时间足够去泡壶茶甚至下楼吃碗麻辣烫。这时候创造者坐在屏幕前假装思考人生，其实只是在等进度条。

为什么静态站点越用越慢？难道内容变多了，就必须全量重编译一遍？

答案肯定是否定的。自然界中的树，一层层年轮叠加，是增量生长，网站内容应该像年轮一样，也可以增量增长。

**RustPress** 就是为了解决这个问题而手搓出来的开源静态博客引擎。纯 Rust 编写、零后端依赖、单一可执行文件，没有动辄几百兆、连光线都能吸进去的 `node_modules` 黑洞。

它已经完成了，下面即是它的 Github 开源仓库及 Crates 类库链接：
- GitHub 仓库：https://github.com/rixingyike/rustpress
- Crates.io 类库：https://crates.io/crates/rustpress

### 核心解法：两个关键设计

除了 Rust 带来的内存安全与原生速度性能，RustPress 在架构上主要靠个设计解决内容增长而性能衰减的问题：

1. **倒分页布局（Reverse Pagination）**：新发布的内容永远排在最新页，已经生成并被搜索引擎收录的历史页面，其 HTML 与静态 URL 永久固化，不会因为加了一篇新文章就产生大面积重排、重新编译。
2. **毫秒级增量编译**：改了哪篇就单编译哪篇，绝不把全站上万个 HTML 文件重新生成一遍。

有了这两点，你用 RustPress 撰写第 1 篇文章和写第 10000 篇文章，体验几乎没有任何区别。当然对于个人创作者，它还有一个最大的优点：它是静态博客，托管在 Github 或 Gitee 上，完全免费，无需服务器。你只需要偏安于一隅，潜心研究你的学问，撰写你的心得，它默默帮你记录，却不会增加你的负担。

### 架构设计：静态固化与动态交互的边界

技术选型往往伴随着取舍：静态生成能带来免维护、抗高并发与永久存证的确定性；但若一味执念于「纯静态」，强行在前端用 JS 弯道实现所有数据库交互，系统便可能会退化为臃肿的黑盒。

RustPress 确立的架构边界非常清晰：**将具备长期不变性的文章、专栏、标签与样式资产，完全推向静态编译与 CDN 边缘固化；而将评论鉴权、实时点赞等即时状态以极其简约且免费的方式实现**。静态求其稳固，动态取其实用，两者各安其位。

本专栏是为了方便读者使用 RustPress 而撰写的，共分为四大部分：**安装与部署**、**核心配置**、**内容创作** 与 **主题定制**。每一篇都配有可直接复制的实操代码与避坑指南，帮你快速搭起属于自己的高性能数字花园。
