# GitHub CI/CD 自动化部署

为什么很多人的博客写着写着就断更了？除了工作忙，一个隐蔽的罪魁祸首就是「发布流程太有仪式感」：写完两行字，要先本地跑命令打包，再打开 FTP 或者手动敲指令往服务器传，一旦忘了拷某张配图或者本地环境差了一个小版本，整站瞬间白屏。折腾完这一圈，只想把电脑合上发誓下个月再写。

最舒服的写作体验应该是：**本地只管码字，敲下 `git push` 关掉电脑，剩下的编译、打包、上线全部由云端流水线自动搞定**。

本篇讲解如何用 **GitHub Actions** 为 RustPress 配置全自动 CI/CD 部署流水线。

---

## 一、自动化构建全流程

```text
┌─────────────────┐      git push      ┌─────────────────────────────┐
│  本地写好 Markdown │ ─────────────────> │  GitHub Markdown 源码库(main) │
│ (source/*.md)   │                    └──────────────┬──────────────┘
└─────────────────┘                                   │ 触发 Actions
                                                      ▼
┌────────────────────────────────────────────────────────────────────┐
│                    GitHub Actions 自动化流水线                      │
│                                                                    │
│  1. 拉取完整 Git Log（精准提取文章最后修改时间戳）                   │
│  2. 自动配置 Rust 环境并缓存安装产物                                 │
│  3. 生产编译（rustpress -m source build -o public）                │
│  4. 同步 CNAME / ads.txt 等根目录资产                               │
│  5. 将 public/ 自动推送到 Pages 分支或独立部署仓库                   │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │ 自动发布完毕
                                  ▼
                    ┌───────────────────────────┐
                    │ 线上即刻访问：yishulun.com  │
                    └───────────────────────────┘
```

## 二、配置 GitHub Actions 工作流

在博客仓库根目录下创建文件 `.github/workflows/deploy.yml`：

```yaml
name: Deploy RustPress Blog

on:
  # push 到 main 分支时自动触发
  push:
    branches: [main]
  # 支持在 GitHub 网页上手动点击触发
  workflow_dispatch:

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      # 1. 检出仓库代码
      # fetch-depth: 0 必加！拉取完整提交历史，用于文章修改时间的精准识别
      - name: Checkout Source Code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      # 2. 准备 Rust 工具链
      - name: Setup Rust Toolchain
        uses: dtolnay/rust-toolchain@stable

      # 3. 启用编译缓存，后续几十秒内搞定
      - name: Setup Rust Cache
        uses: Swatinem/rust-cache@v2

      # 4. 缓存 Cargo 安装产物
      - name: Cache Cargo Binaries
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/bin/
            ~/.cargo/registry/index/
            ~/.cargo/registry/cache/
            ~/.cargo/git/db/
          key: ${{ runner.os }}-cargo-rustpress-${{ hashFiles('**/Cargo.lock') }}
          restore-keys: |
            ${{ runner.os }}-cargo-rustpress-

      # 5. 安装最新稳定版 RustPress
      - name: Install RustPress CLI
        run: |
          if ! command -v rustpress &> /dev/null; then
            cargo install rustpress --locked
          fi

      # 6. 打印版本确认
      - name: Verify RustPress Version
        run: rustpress -V

      # 7. 编译生成纯静态文件到 public 目录
      - name: Build Static Site
        run: rustpress -m source build -o public

      # 8. 拷贝根目录关键资产（CNAME、谷歌广告认证、重定向规则）
      - name: Copy Root Static Assets
        run: |
          cp source/CNAME public/ 2>/dev/null || true
          cp source/ads.txt public/ 2>/dev/null || true
          cp source/_redirects public/_redirects 2>/dev/null || true

      # 9. 部署方案 A：推送到独立的 GitHub Pages 仓库（如 username.github.io）
      # 请将下面的用户名和仓库名换成你自己的
      - name: Deploy to External GitHub Pages Repo
        uses: cpina/github-action-push-to-another-repository@v1.7.2
        env:
          API_TOKEN_GITHUB: ${{ secrets.PERSONAL_ACCESS_TOKEN }}
        with:
          source-directory: public/
          destination-github-username: rixingyike
          destination-repository-name: rixingyike.github.io
          user-email: 9830131@qq.com
          target-branch: "main"
```

## 三、两种部署形态与密钥配置

针对最终产物的存放位置，有两种典型方案：

### 方案 A：发布到独立仓库（如 `username.github.io`）

如果你习惯把 Markdown 源码存一个私有库，而把生成的 HTML 产物丢给专门的公开库 `username.github.io`：

1. 打开 GitHub -> **Settings** -> **Developer Settings** -> **Personal access tokens (classic)**；
2. 点击 **Generate new token**，勾选 `repo` 完整权限，生成并复制 Token；
3. 进入 Markdown 源码仓库 -> **Settings** -> **Secrets and variables** -> **Actions**；
4. 点击 **New repository secret**：
   - **Name**：`PERSONAL_ACCESS_TOKEN`
   - **Value**：粘贴刚才复制的 Token。

---

### 方案 B：同一仓库部署到 `gh-pages` 分支（最简单，无需手动建 Token）

如果你希望源码和产物放在同一个仓库，直接用 `gh-pages` 分支托管：

把 workflow 里的第 9 步替换为官方生态的 `peaceiris/actions-gh-pages`：

```yaml
# 记得在 jobs 同级加上写入权限
permissions:
  contents: write

# ... 前面 1-8 步保持不变 ...

      # 9. 部署方案 B：发布到本仓库的 gh-pages 分支
      - name: Deploy to gh-pages Branch
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
          publish_branch: gh-pages
          commit_message: "docs: auto deploy with RustPress [skip ci]"
```

> **提示**：方案 B 使用 GitHub 内置的 `${{ secrets.GITHUB_TOKEN }}`，**完全不用手动生成任何个人密钥**。

---

## 四、在 GitHub Pages 中启用服务

根据你选的方案，进入对应仓库开启 Pages 托管：

- **方案 A（独立仓库 `username.github.io`）**：  
  进入 `username.github.io` -> **Settings -> Pages**，Branch 选择 `main`，目录选 `/ (root)`，点击 **Save**。
- **方案 B（单仓库 `gh-pages` 分支）**：  
  进入源码仓库 -> **Settings -> Pages**，Branch 选择 `gh-pages`，目录选 `/ (root)`，点击 **Save**。

## 五、验证部署上线

做完以上配置后，在本地测试一次完整链路：

1. 本地执行 `git add . && git commit -m "feat: setup rustpress actions" && git push origin main`；
2. 登录 GitHub 进入仓库的 **Actions** 面板，能看到任务正在跑；
3. 几十秒后任务亮起绿勾（`Success`）；
4. 浏览器打开你的 GitHub Pages 地址（或绑定的域名），网站已成功更新。

如果不需要 GitHub 默认的二级域名，想绑定自己的独立域名，直接在 `source/` 目录下建一个 `CNAME` 文件写上域名即可。

> **辩证权衡：云端流水线 vs 本地就地构建**  
> 云端 Actions 托管能杜绝本地环境污染、统一编译基准，支持多设备随时提交（正）；但在极端断网或平台 Runner 排队时，完全依赖云端会丧失即时发布的自主权（反）。  
> **边界原则**：常态化写作与发布托付给 GitHub Actions 保证一致性；本地始终保留一份可执行的 `rustpress build` 作为离线应急底牌（合）。
