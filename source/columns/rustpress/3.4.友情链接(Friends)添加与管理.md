# 友情链接 (Friends) 添加与管理

早期的个人网站之所以充满生命力，很大程度上得益于博主之间真诚交换「友情链接」。一个个互相关联的独立站点，共同织成了一张去中心化的中文互联网知识网络。

在很多传统博客里，维护友链堪称灾难：要么是在 HTML 里手写一长串杂乱无章的超链接；要么是换完友链过了半年去对方网站一看，自己的名字已经被塞进了字号 8px、藏在页脚折叠菜单最深处的角落中。

在 RustPress 中，维护友链不再是手写一串混乱的 HTML 链接列表。系统提供了结构化的 **友情链接模型（Friends）**，以自适应卡片网格呈现，支持自定义头像、权重排序与申请说明。

---

## 一、友链目录规范

所有友情链接存放在 `source/friends/` 目录下：

```text
source/friends/
├── README.md                 # 友链总览主页与申请规范（必须）
├── assets/                   # 友链专属头像与 Logo
│   ├── tvp.ico
│   ├── rust-lang_logo.png
│   └── friend-avatar.jpg
├── 1.md                      # 单个友链定义
├── 2.md
└── 3.md
```

---

## 二、单条友链 Markdown 格式规范

在 `source/friends/` 下新建一个 Markdown 文件（如 `1.md`），填入 Frontmatter：

```yaml
---
title: "腾讯云最具价值专家 (TVP)"
slug: "tvp"
link: "https://cloud.tencent.com/tvp"
description: "腾讯云最具价值专家计划，汇聚行业顶尖技术精英与布道者。"
avatar: "assets/tvp.ico"
domain: "cloud.tencent.com"
weight: 1
layout: friend
createTime: 2025-11-05 08:00:00
---
```

### 属性字段速查表

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `title` | `String` | 友链网站名称或博主昵称。 |
| `link` | `String` | 目标跳转 URL。 |
| `description` | `String` | 站点一句话简述（展示于卡片下方）。 |
| `avatar` | `String` | 头像路径，可为 `assets/` 相对路径或外部 URL。 |
| `domain` | `String` | 友链域名标识。 |
| `weight` | `Integer` | 排序权重，数字越小排在越前面。 |
| `layout` | `String` | 固定指定为 `friend`。 |

---

## 三、友链总览与申请说明（`README.md`）

`source/friends/README.md` 是友链页面的头部说明，在这里写明本站信息与互换友链的要求：

```yaml
---
title: "友情链接"
layout: friends
description: "海内存知己，天涯若比邻。欢迎志同道合的技术博主交换友链。"
createTime: 2025-11-05 08:00:00
---
```

## 四、前端呈现效果

构建完成后，访问 `/f/` 页面：
- 顶部展示 `README.md` 的申请说明与本站档案；
- 下方以卡片网格渲染所有友链（圆形头像、网站名、描述与外链跳转）；
- 底部自动挂载原生评论区，同行访客可以直接在下方提交申请。

> **辩证审视：开放连接 vs 质量把关**  
> 积极交换友链能构建去中心化的技术同伴网络（正）；但若无准入底线、来者不拒，博客容易被死链、镜像采集站与商业广告站拖累信任分（反）。  
> **边界原则**：以「是否具备持续的原创生命力与技术共鸣」作为唯一准入基准，重质不重量并定期清理失效死链（合）。
