# 专栏与分类法路径配置

你有没有在社交软件或微信群里分享过长得让人窒息的链接？一长串中文 URL 编码 `%E4%B8%93%E6%A0%8F` 加上四五层深嵌套目录，不仅手机端换行挤成一团像黑客乱码，读者点开的欲望也直接折半。

**短小、精炼且语义明确的 URL 路径**，不仅读者看着舒服，在搜索引擎（SEO）眼里也是权重更高的优质结构。

RustPress 提供了非常灵活的 **`[taxonomies]` 分类体系与路由别名映射机制**，允许你自由定制专栏、短动态、标签、分类、开源项目、出版著作与历史归档的对外访问路径。

---

## 一、`[taxonomies]` 默认路由映射表

打开 `config.toml`，找到 `[taxonomies]` 配置区块：

```toml
# ==============================================================================
# 分类法与内容体系 URL 路由别名映射 [taxonomies]
# ==============================================================================
[taxonomies]
columns = "/c"        # 专栏体系（系列长文/连载课程）
tweets = "/t"         # 短动态（闲言碎语/去中心化微动态）

categories = "/cat"   # 文章分类体系
tags = "/tag"         # 标签云体系

projects = "/p"       # 个人开源项目与软件作品
works = "/w"          # 个人出版著作与书籍

archives = "/a"       # 历史按年份月份归档
friends = "/f"        # 友情链接页面
about = "/about.html" # 个人作者简介独立页
```

---

## 二、各类内容模型的 URL 生成规则

当你在 `config.toml` 里配置了别名后，静态编译时会自动映射出干净短小的 URL：

| 内容模型 | 源码存放目录 | 路由配置项 | 最终对外 URL 示例 |
| :--- | :--- | :--- | :--- |
| **专栏总览** | `source/columns/` | `columns = "/c"` | `https://yishulun.com/c/` |
| **单个专栏** | `source/columns/rustpress/` | `columns = "/c"` | `https://yishulun.com/c/rustpress/` |
| **专栏文章** | `source/columns/rustpress/1.1.md`| `columns = "/c"` | `https://yishulun.com/c/rustpress/1.1.安装与本地开发预览.html` |
| **短动态闲言** | `source/tweets/` | `tweets = "/t"` | `https://yishulun.com/t/` |
| **全站分类** | `source/` 目录结构 | `categories = "/cat"` | `https://yishulun.com/cat/` |
| **单分类列表** | 文章 Frontmatter | `categories = "/cat"` | `https://yishulun.com/cat/后端/` |
| **全站标签** | 文章 Frontmatter | `tags = "/tag"` | `https://yishulun.com/tag/` |
| **单标签列表** | 文章 Frontmatter | `tags = "/tag"` | `https://yishulun.com/tag/Rust/` |
| **开源项目** | `source/projects/` | `projects = "/p"` | `https://yishulun.com/p/` 或 `/p/rustpress.html` |
| **出版著作** | `source/works/` | `works = "/w"` | `https://yishulun.com/w/` 或 `/w/miniprogram-0-1.html` |
| **历史归档** | `source/` 时间轴 | `archives = "/a"` | `https://yishulun.com/a/` |
| **友情链接** | `source/friends/` | `friends = "/f"` | `https://yishulun.com/f/` |

## 三、与顶部导航菜单（`[[menu.main]]`）协同

修改了 `[taxonomies]` 的路径别名后，要确保 `[[menu.main]]` 导航菜单中的链接与其保持对应：

```toml
[[menu.main]]
name = "首页"
url = "/"
weight = 1

[[menu.main]]
name = "归档"
url = "/a/"
weight = 2

[[menu.main]]
name = "分类"
url = "/cat/"
weight = 3

[[menu.main]]
name = "标签"
url = "/tag/"
weight = 4

[[menu.main]]
name = "专栏"
url = "/c/"
weight = 5

[[menu.main]]
name = "友链"
url = "/f/"
weight = 6

[[menu.main]]
name = "项目"
url = "/p/"
weight = 7

[[menu.main]]
name = "关于"
url = "/about.html"
weight = 8
```

> **注意**：在 `default` 主题中顶部常驻有横向导航栏；在 `light` 主题中采用极简留白设计，主导航以轻量抽屉或页脚形式呈现。

## 四、两种风格的定制建议

- **喜欢经典完整单词**：如果你偏好 Hugo 或 Hexo 的习惯，可以把别名改为全拼：
  `columns = "/columns"`, `categories = "/categories"`, `tags = "/tags"`, `archives = "/archives"`。
- **喜欢极简短链**：推荐保留默认的单字母缩写（`/c`, `/t`, `/cat`, `/tag`, `/p`, `/w`, `/a`, `/f`）。在手机端展示、剪贴板复制和社交传播时，短链接既优雅又不易断行。

> **辩证权衡：极简短链 vs 语义完整**  
> 单字母短路由能极致压缩 URL 长度，防止在社交平台分享时折行破碎；但过度精简会牺牲 URL 自解释的语义直观性。  
> **边界原则**：顶层分类采用短路由压缩目录层级，底层具体资源（文章/专栏名）保留清晰语义。分界在于「分类层级求传播紧凑，实体内容求语义自明」。

除了日常博文，RustPress 的这套分类法还把开源项目、出版著作与短动态全部纳入了统一的静态路由体系中。
