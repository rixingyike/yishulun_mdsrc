# GitHub 原生评论与点赞系统配置

很多静态博客依赖于第三方的 iframe 嵌入式评论插件（如 Giscus 或 Disqus），这类方案往往存在 iframe 跨域白屏、样式无法与网站深度融合、加载性能损耗以及依赖第三方服务稳定性的问题。

**RustPress 内置了全新自研的 GitHub Issues 原生评论与点赞插件系统（`rustpress-comments`）**。它以原生 DOM 方式直接渲染在页面正文中，秒级加载、自适应主题配色，并深度支持文章点赞 👍、评论计数与 Markdown 实时排版。

---

## 一、RustPress 原生评论系统的核心特色

1. **原生 DOM 深度融合**：告别任何 iframe 限制，完全继承当前主题（`light` / `default`）的字体、配色与排版样式。
2. **点赞与评论一体化**：不仅支持 Markdown 评论互动，还原生支持一键点赞（自动同步至 GitHub Issue 的 `+1` Reaction 反应）。
3. **数据完全归属于己**：所有互动数据直接作为 Issue / Comments 持久化存储在您指定的 GitHub 仓库中，永不丢失。
4. **Issue 自动按需关联**：当某篇博文首次被点赞或评论时，系统会自动以文章标题和 URL 路径创建一条对应的 Issue，无需站长手动预建。
5. **只读模式平滑降级**：即使未配置 OAuth 登录凭据，访客依然能够正常浏览已有评论与点赞总数。

## 二、三行极简全局配置

与传统方案需要配置繁复的 GraphQL Node ID（如 `repo_id`、`category_id` 等）不同，RustPress 的评论插件配置极其简洁：

打开博客根目录下的 `config.toml`，仅需配置 `[comments]` 小节：

```toml
# ==============================================================================
# 评论与点赞互动系统配置 [comments]
# ==============================================================================
[comments]
enabled = true                                 # 是否启用全站评论与点赞插件
repo = "rixingyike/yishulun.com_discus"        # 存放评论 Issue 的 GitHub 公开仓库 (格式: 用户名/仓库名)
github_client_id = "0cdfd84658051b0f7de6"      # GitHub OAuth App 的 Client ID
```

### 配置项说明：
- **`enabled`**（布尔值）：全局功能总开关。设为 `true` 开启，`false` 关闭。
- **`repo`**（字符串）：指定用来存放评论 Issues 的公开 GitHub 仓库。
- **`github_client_id`**（字符串，可选）：GitHub OAuth App 的 Client ID。用于访客一键使用 GitHub 账号登录发表评论或点赞。如果留空，评论区将以只读模式展示。

## 三、准备 GitHub 仓库与 OAuth App

### 1. 新建评论专用公开仓库
1. 登录 GitHub，点击右上角 **New repository**。
2. 填写仓库名（如 `yishulun.com_discus`），权限必须选择 **Public（公开）**。
3. 确保仓库开启了 **Issues** 功能（默认开启）。

### 2. 创建 GitHub OAuth App
为了让读者能通过 GitHub 账号授权并发表评论，需要在 GitHub 注册一个 OAuth App：

1. 进入 GitHub -> **Settings** -> **Developer settings** -> **OAuth Apps**。
2. 点击 **New OAuth App**，填写基本信息：
   - **Application name**：您的博客名称（如 `艺述论评论系统`）。
   - **Homepage URL**：博客首页地址（如 `https://yishulun.com`）。
   - **Authorization callback URL**：先暂时填入您的博客地址，稍后部署完 Cloudflare Worker 后替换为 Worker 的 `/callback` 地址。
3. 点击 **Register application**，即可获得该 App 的 **Client ID** 和 **Client Secret**。
4. 将 **Client ID** 填入 `config.toml` 的 `github_client_id` 中。

## 四、部署 Cloudflare Worker OAuth 代理服务（线上免服务器方案）

### 为什么需要 Worker 代理？
在 GitHub OAuth 授权标准中，前端用临时授权码 `code` 换取 `access_token` 时，必须提供私密的 `Client Secret`。由于纯静态博客没有后端服务器，**绝对不能把 `Client Secret` 暴露在前端 JS 代码中**。

RustPress 官方提供了开箱即用的 [`rustpress-comments-oauth-worker.js`](https://github.com/rixingyike/rustpress/blob/main/rustpress-comments-oauth-worker.js)，部署在免费的 Cloudflare Workers 上，不仅零成本、免服务器维护，还能安全加密存储凭据并防止开放重定向攻击。

```
访客点击登录 ──> GitHub 授权 ──> Cloudflare Worker (携带 Secret 安全换取 Token) ──> 安全跳回文章页
```

### 部署 3 步走：

#### 步骤 1：在 Cloudflare 创建 Worker
1. 登录 [Cloudflare 控制台](https://dash.cloudflare.com/)。
2. 进入 **Workers 和 Pages (Workers & Pages)** -> 点击 **创建 (Create Application)** -> **创建 Worker (Create Worker)**。
3. 给 Worker 起一个名字（如 `rustpress-comments-oauth`），点击 **部署 (Deploy)**。
4. 点击 **编辑代码 (Edit code)**，清空原有模板内容，将 RustPress 仓库中的 `rustpress-comments-oauth-worker.js` 代码完整复制粘贴进去，点击 **保存并部署 (Save and Deploy)**。
5. 复制分配给该 Worker 的公网域名（例如 `https://rustpress-comments-oauth.your-subdomain.workers.dev`）。

#### 步骤 2：配置加密环境变量
进入该 Worker 详情页 -> **设置 (Settings)** -> **变量 (Variables)**，点击 **添加 (Add)** 如下 3 个变量：

| 变量名 (Variable name) | 填写内容示例 | 是否加密 | 说明 |
| :--- | :--- | :--- | :--- |
| `GITHUB_CLIENT_ID` | `0cdfd84658051b0f7de6` | 否 | 对应 GitHub App 的 Client ID |
| `GITHUB_CLIENT_SECRET` | `48a2...` | **是（点击 Encrypt 加密）** | 对应 GitHub App 的 Client Secret |
| `BLOG_DOMAIN` | `https://yishulun.com` | 否 | 博客域名（防范恶意开放重定向攻击） |

添加完毕后，点击 **保存并部署**。

#### 步骤 3：回填 GitHub OAuth 回调地址
回到 GitHub 的 OAuth App 设置页面，将 **Authorization callback URL** 更新为 Worker 的回调路径：

```text
https://rustpress-comments-oauth.your-subdomain.workers.dev/callback
```
*(如果给 Worker 绑定了自定义独立域名，则为 `https://oauth.yourdomain.com/callback`)*

到这里，评论系统就配置完了。感谢 cloudflare，不然的话我们要实现这项动态功能，非得用服务器不可。cloudflare 提供的 Worker 服务是免费的，你也可以使用。

## 五、单篇文章评论开关与控制

全局启用评论系统后，所有博文、专栏文章及著作页面默认均开放互动。

如果您希望对某篇特定文章（或关于页、隐私协议）**单独关闭评论区**，只需在文章头部的 Frontmatter 中添加 `comments: false`：

```yaml
---
title: "作者简介与免责声明"
layout: about
comments: false
---
```

主题模板在检测到 `page.comments == false` 时，会自动隐藏底部的评论输入框、评论列表与评论计数按钮，灵活可控。
