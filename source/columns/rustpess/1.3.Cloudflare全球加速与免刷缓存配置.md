# Cloudflare 全球加速与免刷缓存配置

将基于 GitHub Pages 托管的 RustPress 博客接入 Cloudflare，不仅能获得免费全球 CDN 加速、DDoS 防护与自动化 SSL 证书，还能通过 **“静态资产全球缓存 + HTML 实时穿透”** 策略，在保障全站极速访问的同时，发布新博文或更新内容时**无需手动清除缓存**，几乎全网秒级实时同步。

还有，这一切都是免费的，对个人创作者十分友好。

---

## 一、添加站点与接管 DNS 解析

将域名解析权托管给 Cloudflare，建立全球边缘流量入口：

1. **添加站点**：登录 [Cloudflare 控制台](https://dash.cloudflare.com/)，输入您的主域名（如 `yishulun.com`），选择 **Free（免费）计划**。
2. **修改 Nameservers**：前往域名注册商控制台（阿里云、腾讯云、Namecheap 等），将原有的 DNS 服务器地址替换为 Cloudflare 分配的两个 NS 地址。
3. **配置 DNS 代理记录**：
   - 进入 **DNS -> 记录 (Records)** 页面，添加 `CNAME` 记录（根域名 `@` 与 `www`）。
   - 目标指向 GitHub Pages 源站地址（例如 `username.github.io`）。
   - **关键设置**：确保 **代理状态** 为 **已代理（橙色小云朵）**，使流量全部经由边缘节点转发。

| 类型 (Type) | 名称 (Name) | 内容 (Content) | 代理状态 (Proxy status) |
| :--- | :--- | :--- | :--- |
| `CNAME` | `@` | `username.github.io` | **已代理（橙色小云朵）** |
| `CNAME` | `www` | `username.github.io` | **已代理（橙色小云朵）** |

## 二、配置 SSL/TLS 加密模式

针对 GitHub Pages 自带 HTTPS 的源站，必须正确设置加密模式以避免 301 重定向死循环：

1. **设置加密模式**：进入 **SSL/TLS -> 概述 (Overview)**，将加密模式切换为 **完全 (Full)** 或 **完全（严格）(Full Strict)**。
2. **强制全站 HTTPS**：进入 **SSL/TLS -> 边缘证书 (Edge Certificates)** 页面，开启以下安全选项：
   - **始终使用 HTTPS (Always Use HTTPS)**：自动将 HTTP 请求重定向至 HTTPS。
   - **TLS 1.3**：提升握手速度与安全性。
   - **自动 HTTPS 重写 (Automatic HTTPS Rewrites)**：防止站内混合内容警告。

## 三、配置全局缓存与网络优化（免刷缓存机制）

无需为 HTML 创建特殊的强缓存规则，依托 Cloudflare 默认策略即可实现最佳的动静分离：

### 1. 动静分离加速机制
- **HTML 网页**：默认直接请求 GitHub Pages 源站。在 GitHub 提交新文章或更新页面后，访客刷新即可**实时展现最新内容**，彻底告别手动点击“清除缓存”。
- **静态资产（JS / CSS / 图片 / 字体）**：Cloudflare 自动将其缓存在全球边缘节点，大幅缩短首屏与二次加载时间。

### 2. 浏览器缓存与压缩优化
- **浏览器缓存 TTL**：进入 **缓存 -> 配置 (Caching -> Configuration)**，将全局 **浏览器缓存 TTL** 设为 `4 小时`，降低重复访客的网络压力。
- **传输压缩与加速**：进入 **速度 -> 优化 (Speed -> Optimization)**，开启 **Brotli 压缩** 与 **Early Hints (103)**，缩减传输体积并提前向浏览器推送关键渲染资源。

---

## 四、清理多余的 HTML 缓存规则

如果此前为站点创建过全站 HTML 缓存规则，建议进行清理以保障发布实时性：

1. 前往 **缓存 -> Cache Rules** 页面。
2. 找到名为 `cache-all-html` 或其它名称的 HTML 强缓存规则，将其开关切换为**停用**或直接**删除**。
3. 进入 **缓存 -> 配置**，执行最后一次 **清除所有内容 (Purge Everything)**。

完成配置后，您的博客既享有全球 CDN 节点对静态资源的高速分发，又具备了内容发布的及时性。

如果你选择配置了`cache-all-html`缓存，也不是不可以，该项配置可以提高缓存，但新内容发布时，会导致旧内容无法及时更新，依据配置大概有 4 小时的缓存，如果能够接受延后，则可以选择保留该缓存规则。
