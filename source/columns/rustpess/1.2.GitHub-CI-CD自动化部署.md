# GitHub CI/CD 自动化部署

在静态博客的现代工作流中，理想的写作体验应当是：**本地专注于 Markdown 内容创作与提交（`git commit && git push`），云端自动触发流水线完成环境安装、静态文件编译与生产发布**。

本篇将详细讲解如何通过 **GitHub Actions** 为 RustPress 配置工业级 CI/CD 自动化流水线。

---

## 一、自动化构建流程架构

```
┌─────────────────┐      git push      ┌─────────────────────────────┐
│  本地撰写文章     │ ─────────────────> │  GitHub Markdown 仓库 (main) │
│ (source/*.md)   │                    └──────────────┬──────────────┘
└─────────────────┘                                   │ 触发 Actions
                                                      ▼
┌────────────────────────────────────────────────────────────────────┐
│                    GitHub Actions CI/CD 流水线                      │
│                                                                    │
│  1. Checkout 代码 (含完整 Git Log 用于文章更新时间)                    │
│  2. 安装 Rust 工具链与 RustPress (`cargo install rustpress`)         │
│  3. 生产环境编译 (`rustpress -m source build -o public`)             │
│  4. 同步 CNAME / ads.txt / _redirects 根文件                         │
│  5. 自动化部署产物至静态发布分支 / 独立 GitHub Pages 仓库                │
└─────────────────────────────────┬──────────────────────────────────┘
                                  │ 发布完成
                                  ▼
                    ┌───────────────────────────┐
                    │ 线上访问：https://yishulun.com│
                    └───────────────────────────┘
```

## 二、配置 GitHub Actions 工作流文件

在您的博客仓库根目录下创建文件 `.github/workflows/deploy.yml`：

```yaml
name: Deploy RustPress Blog

on:
  # 每当 push 到 main 分支时自动触发
  push:
    branches: [main]
  # 支持在 GitHub Actions 网页控制台手动点击触发
  workflow_dispatch:

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      # 1. 检出仓库代码
      # fetch-depth: 0 非常关键，确保拉取完整的提交历史，用于文章最后修改时间戳的精准提取
      - name: Checkout Source Code
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      # 2. 安装 Rust 工具链
      - name: Setup Rust Toolchain
        uses: dtolnay/rust-toolchain@stable

      # 3. 启用 Rust 编译缓存，大幅加速后续工作流执行
      - name: Setup Rust Cache
        uses: Swatinem/rust-cache@v2

      # 4. 缓存 Cargo Registry 与安装产物
      - name: Cache Cargo Binaries
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/bin/
            ~/.cargo/registry/index/
            ~/.cargo/registry/cache/
            ~/.cargo/git/db/
          key: ${{ runner.os }}-cargo-rustpress-${{ hashFiles('**/Cargo.lock') }}
          restore-keys: |
            ${{ runner.os }}-cargo-rustpress-

      # 5. 安装最新稳定版 RustPress
      - name: Install RustPress CLI
        run: |
          if ! command -v rustpress &> /dev/null; then
            cargo install rustpress --locked
          fi

      # 6. 验证 RustPress 安装
      - name: Verify RustPress Version
        run: rustpress -V

      # 7. 编译生成纯静态网站至 public 目录
      - name: Build Static Site
        run: rustpress -m source build -o public

      # 8. 拷贝根级特殊静态文件（CNAME、谷歌广告认证、重定向规则）
      - name: Copy Root Static Assets
        run: |
          cp source/CNAME public/ 2>/dev/null || true
          cp source/ads.txt public/ 2>/dev/null || true
          cp source/_redirects public/_redirects 2>/dev/null || true

      # 9. 部署方案 A：部署到独立目标仓库（如 username.github.io）
      # 下面的 Github 用户名、仓库名要根据需要修改成你自己的
      - name: Deploy to External GitHub Pages Repo
        uses: cpina/github-action-push-to-another-repository@v1.7.2
        env:
          API_TOKEN_GITHUB: ${{ secrets.PERSONAL_ACCESS_TOKEN }}
        with:
          source-directory: public/
          destination-github-username: rixingyike
          destination-repository-name: rixingyike.github.io
          user-email: 9830131@qq.com
          target-branch: "main"
```

## 三、配置 GitHub Secrets 权限密钥

如果您采用将构建产物推送到独立仓库（如 `username.github.io`）的方案：

1. 打开 GitHub -> **Settings** -> **Developer Settings** -> **Personal access tokens (classic)**。
2. 点击 **Generate new token**，勾选 `repo` 完整权限，生成密钥并复制。
3. 进入博客 Markdown 源码仓库 -> **Settings** -> **Secrets and variables** -> **Actions**。
4. 点击 **New repository secret**：
   - **Name**：`PERSONAL_ACCESS_TOKEN`
   - **Value**：粘贴刚才复制的 GitHub Token。

> **方案 B（同一仓库部署到 gh-pages 分支）**：
> 如果您希望直接部署在当前仓库的 `gh-pages` 分支，可以使用官方生态的 `peaceiris/actions-gh-pages@v4`，直接传入 GitHub 自动提供的 `${{ secrets.GITHUB_TOKEN }}` 即可，**无需手动创建任何 Personal Access Token**！

### 方案 B 完整工作流示例（同一仓库部署到 `gh-pages` 分支）

在当前仓库创建 `.github/workflows/deploy.yml`：

```yaml
name: Deploy RustPress Blog to gh-pages

on:
  push:
    branches: [main]
  workflow_dispatch:

# 必须赋予 actions 写入仓库分支的权限
permissions:
  contents: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
      # 1-8 步配置与方案 A 相同
      
      # 9. 部署方案 B：部署到当前仓库的 gh-pages 分支
      - name: Deploy to gh-pages Branch
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public
          publish_branch: gh-pages
          commit_message: "docs: auto deploy with RustPress [skip ci]"
```

## 四、开启 GitHub Pages 访问服务

根据您选择的部署方案，开启对应的 GitHub Pages 服务：

- **针对方案 A（独立仓库，如 `rixingyike.github.io`）**：
  1. 进入 `username.github.io` 仓库 -> **Settings -> Pages**。
  2. **Branch** 选择 `main`，目录选择 `/ (root)`，点击 **Save**。

- **针对方案 B（同一仓库部署到 `gh-pages` 分支）**：
  1. 进入当前博客仓库 -> **Settings -> Pages**。
  2. **Branch** 选择 `gh-pages`，目录选择 `/ (root)`，点击 **Save**。

## 五、安装与部署上线成功判定标准

当您完成以上配置并执行第一次推送后：

1. 本地执行 `git add . && git commit -m "feat: init rustpress blog" && git push origin main`。
2. 打开 GitHub 仓库的 **Actions** 面板，可以看到工作流正在运行。
3. 约 30~60 秒后，Workflow 显示全部绿色对勾（`Success`）。
4. 在浏览器中打开您的专属 GitHub Pages 网址（如 `https://username.github.io`）或已绑定的独立域名，能够正常加载网站首页、专栏、博文与样式。

如果不想使用 Github 提供的二级域名，使用自己的独立域名，在 source 目录下创建 CNAME 文件，将域名写入其中即可。
