# 独立域名与 CNAME 解析配置

拥有一个简洁易记的独立顶级域名（如 `yishulun.com`），不仅能够彰显专业创作者形象，更是沉淀长期外部反向链接与搜索引擎权威度（Domain Authority）的核心基石。

本篇将详细讲解从域名解析配置、RustPress `CNAME` 文件管理，到 GitHub Pages 绑定与强制 HTTPS 跳转的完整流程。

---

## 一、创建 `source/CNAME` 文件

GitHub Pages 与大多数静态托管平台通过根目录下的 `CNAME` 文件来识别要绑定的自定义域名。

### 1. 写入域名内容
在博客的 `source/` 根目录下新建 `CNAME` 文件（注意：无任何文件扩展名），内容仅写入您的正式域名：

```text
yishulun.com
```

### 2. 自动化构建同步
确保您的 CI/CD 部署脚本在每次编译后将该文件复制到 `public/` 产物目录中：

```bash
cp source/CNAME public/CNAME
```

> **重要提示**：如果没有在源码中持久化维护 `CNAME` 文件，每次 GitHub Actions 覆盖推送后，GitHub Pages 的自定义域名设置会被重置，导致域名绑定暂时失效。

---

## 二、DNS 服务商解析记录设置

前往您的域名 DNS 控制台（Cloudflare、腾讯云 DNSPod、阿里云云解析或 Namecheap 等），添加以下解析记录：

### 推荐方案：CNAME 别名解析（配合 Cloudflare 或支持 CNAME Flattening 的 DNS）

| 主机记录 (Host) | 记录类型 (Type) | 记录值 (Target) | TTL |
| :--- | :--- | :--- | :--- |
| `@` (根域名) | `CNAME` | `rixingyike.github.io.` | 自动 / 600 |
| `www` | `CNAME` | `rixingyike.github.io.` | 自动 / 600 |

### 备用方案：A 记录直接指向 GitHub 官方 Anycast 节点 IP

如果您的 DNS 服务商不支持根域名 `@` 配置 CNAME 记录，请添加 4 条 A 记录：

- `185.199.108.153`
- `185.199.109.153`
- `185.199.110.153`
- `185.199.111.153`

---

## 三、在 GitHub Pages 中绑定与开启 HTTPS

1. 进入托管静态文件的 GitHub 仓库（例如 `rixingyike.github.io`）。
2. 点击 **Settings -> Pages**。
3. 在 **Custom domain** 输入框中填入您的独立域名（如 `yishulun.com`），点击 **Save**。
4. GitHub 会自动执行 DNS 检查并签发免费的 Let's Encrypt SSL 证书（通常需要 2~10 分钟）。
5. 证书就绪后，勾选 **Enforce HTTPS（强制 HTTPS）**。

---

## 四、同步更新 RustPress 的 `config.toml`

在正式绑定独立域名后，请确保 `config.toml` 中的 `domain` 与 `base_url` 更新为生产正式域名：

```toml
[site]
name = "艺述论"
# 生产环境绝对域名（必须为 https:// 开头且末尾不带斜杠）
domain = "https://yishulun.com"
base_url = "https://yishulun.com"
```

这能保证生成的 `rss.xml`、`sitemap.xml` 以及所有文章内链均准确指向您的独立域名。

---

## 五、DNS 解析生效测试

在本地终端运行以下命令，验证 DNS 是否已在全球解析生效：

```bash
# 查询 CNAME 别名指向
dig yishulun.com CNAME +short

# 测试 HTTP 状态码与 301 重定向
curl -I https://yishulun.com
```

当返回 `HTTP/2 200` 或 `HTTP/1.1 200 OK` 时，表明独立域名配置完美成功！
